# Supported features

Statuses: **Supported** · **Partial** · **Planned** · **Not planned** · **Blocked**

"Tests" names the test class or golden that covers the row. An unsupported construct always produces a
structured diagnostic; nothing is silently ignored (PROJECT_BRIEF.md 3.3, 14).

**Read the Marks table carefully.** A row says "Supported" only when the engine can *produce* that
construct from an input specification. Where a scene node type exists but nothing encodes data into it
yet, the row says **Renderable** — the geometry draws and hit-tests correctly, but there is no mark
encoder, so a Vega specification cannot ask for it. Six of the twelve mark types are now Supported; see
the scope note in STATUS.md for how much of upstream Vega remains.

## Input

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| Hand-authored scene graph | Supported | `SampleScenes`, `SceneSnapshotTest` | Not a Vega input format | 1 |
| Loading data from a URL | **Supported** | `DataLoaderTest`, `ExampleTriage` | A `url` dataset is fetched through a host-supplied `DataLoader`, read as `json`, `csv`, `tsv` or `dsv`, with `format.property` reaching into a document and `format.parse` giving a tabular column its type. **Denied by default**: a specification is data, often pasted data, and a URL in it asks this process to fetch an address the specification chose — so the host opts in and says what to. `topojson` is reported; it needs projections and is a non-goal | 4 |
| Relative data URLs (`"url": "data/barley.json"`) | **Supported** | `VegaDataLoadersTest`, `FixtureDifferentialTest` (`barley-trellis`, `connected-scatter`) | The shape nearly every published Vega specification uses. `FallbackDataLoader` tries loaders in order, and `VegaDataLoaders.directoryThenNetwork` is the useful arrangement: read from a directory if the file is there, fetch from the base URL if it is not, and — with `cacheDownloads` — write it to that directory so the second run is offline. The default base is `https://vega.github.io/vega/`, the site the gallery is served from, so a relative path under it is the file the example was written against rather than a lookalike. It is a default for *reaching* the data, never for whether to: `DenyLoader` is still what a compiler gets unless a host passes something else. The base URL's host is the allowlist by default, because a specification chooses its own URLs and an unrestricted loader following a relative path is a request-forgery primitive one redirect away | 4 |
| The demo loading a pasted example's data | **Supported** | `DemoActivityTest` (on an API 37 emulator, over a real socket) | The demo opts in with `VegaDataLoaders.directoryThenNetwork(cacheDir, cacheDownloads = true)`, so pasting a gallery example whose data is a relative URL draws the chart rather than an empty pair of axes, and the second paste of the same example needs no network. The allowlist is the one host the base URL names, which is the whole safety argument: this screen compiles text a *user pasted*, and an unrestricted loader would let that text aim the process at any address it liked. Private addresses are refused too, so the allowed host cannot be rebound onto loopback. The device test is where this can be proved at all — the JVM tests use a fake transport, and a missing `INTERNET` permission would show up nowhere earlier | 4 |
| Passing a loader to the chart | **Supported** | `VegaChartControllerTest` | `VegaChartController(loader = ...)`. Until this existed the engine had a loader and no host could opt in to it, which is the same as not having one | 4 |
| Loader policy | **Supported** | `DataLoaderTest` | Ported from the Go loader in `mgilbir/aster`, with the same controls: an allowlist of domains, a base URL for relative references, blocking hosts that resolve to private/loopback/link-local addresses (including the cloud metadata endpoint), and a response-size cap that fails rather than truncating. The policy is re-applied to **every redirect hop**, which a check on the first URL alone misses. `sanitize` is separate from `load` so the decision can be tested without I/O, and is required to be idempotent | 4 |
| Where the policy lives | **Supported** | — | All of it is common Kotlin in `vega-runtime`, including the URI parser and RFC 3986 reference resolution, so the rules cannot drift between platforms. The only seams are `HttpTransport` (one GET, no redirects) and `HostResolver`; `vega-loader` supplies the JVM ones | 4 |
| Pasting a specification into the demo | **Supported** | `DemoActivityTest` (on an API 37 emulator) | The demo's "Paste your own" entry compiles a specification from the clipboard or from an editable field, and shows the diagnostics beneath the chart — the only place they are aimed at a user rather than at a contributor. Three outcomes are worded apart on purpose: it did not compile (the previous chart stays, and saying so matters or the app looks like it ignored the paste); it compiled but something could not be drawn (the chart is not what was asked for); or a property was merely ignored (it very nearly is). Reading the clipboard needs foreground focus on Android 10 and later, so the null path is real and is reported | 5 |
| Compiled Vega JSON | Partial | `SpecCompilerTest`, `FixtureDifferentialTest` | Parses and compiles the subset below, including signals, expressions, 35 transforms, nested group scopes, legends and titles. No group `layout`; it reports a diagnostic. Loaded through `VegaChartController.setSpec`, or `setSpecAsync` to compile off the calling thread | 3 |
| Vega-Lite compilation | Not planned (first release) | — | Compile upstream via `oracle-js/src/compile-vega-lite.js` | — |
| Generic JSON value model | Supported | `VegaValueTest`, `JsonBridgeTest` | Numbers are always `Double` | 0 |
| Dotted / bracketed field paths | Supported | `VegaValueTest` | Malformed paths resolve to null rather than throwing | 0 |
| `config` blocks | **Partial** | `ConfigTest` (upstream vectors), `FixtureDifferentialTest` (`config-theme`, `config-marks`) | The guide blocks: `axis` with its `axisX`/`axisY`, `axisTop`/`axisBottom`/`axisLeft`/`axisRight` and `axisBand` variants, `legend`, the `guide-label` and `guide-title` styles, and `background`/`padding`/`autosize`. Precedence runs style → axis → dimension → side → band → the guide's own properties, verified by setting one property at every level and seeing which drew. A `style` block names its properties the way a **mark** does, so `fill` becomes `labelColor` on the way through — without that the form every Vega-Lite theme uses would set nothing. Also the mark blocks: `config.mark`, the per-mark-type blocks, and named `config.style` blocks a mark opts into through its own `style` property. `config.mark` sits **below** the engine's built-in per-type defaults and `config.{marktype}` sits above them, because upstream's default configuration is itself written into those per-type blocks — so `config.mark.fill` never recolours a rect and `config.rect.fill` does. `config.range`, `config.group` and `config.projection` are reported by name | 6 |
| Unhandled properties reported | **Supported** | `UnhandledPropertiesTest` | Each parser names the properties it *consumes* and reports the remainder, rather than keeping a list of what is missing. Covers axes, scales, legends, titles, marks and encode channels, so a property nobody anticipated — including one upstream adds later — is a diagnostic rather than a silence. Where there is something specific to say about what gets drawn instead, it is said by name: `limit`, for instance, draws the text past the width it was told to stay inside | 5 |

## Marks

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| Group | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`facet-trellis` fixture) | One container per datum, translated by its `x`/`y`, painting its fill and stroke over its declared `width` × `height`. `clip` narrows it. Nests to any depth | 3 |
| Faceting (`from.facet`) | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`facet-trellis` fixture) | `groupby` only, on one or more fields. Cells appear in first-appearance order and each cell's datum is the groupby fields plus `count`, matching the `aggregate` transform upstream inserts. Pre-faceted `facet.field` and extra `facet.aggregate` measures are reported | 3 |
| Value-reference arithmetic (`mult`, `offset`, `exponent`, `round`) | **Supported** | `FixtureDifferentialTest` (`grouped-bar`) | Every value reference accepts all four, applied after the scale in upstream's order — `round(pow(v, e) * m + o)` — and each is itself a value reference, so an offset can be read from the datum: `{"field": "y", "offset": {"field": "height", "mult": 0.5}}` centres a label in a band whose height only the row knows. They had been read on a *scaled* channel only, so `{"field": "x2", "offset": -5}` placed a label at the end of the bar instead of just inside it, with nothing reported | 3 |
| A mark drawn from another mark (`from.data: "<mark name>"`) | **Supported** | `FixtureDifferentialTest` (`radar`, `grouped-bar`, `barley-trellis`) | Marks and datasets share one namespace in Vega, so a mark may be drawn from the *scene items* an earlier named mark produced — which is how a radar chart labels each vertex of its line and closes the ring its rules describe. Each item is the mark's resolved channels plus `datum`, the row behind it, so a label reads `datum.x` for the vertex and `datum.datum.value` for the number. `x` is derived from `xc` or `x2` the way upstream's `adjustSpatial` derives it, and a `rule` is exempt from that as upstream exempts it. Only marks declared **before** the reader are visible, which is upstream's order too; a name that resolves to neither a dataset nor an earlier mark says so in those words | 3 |
| Mark and axis `zindex` | **Supported** | `FixtureDifferentialTest` (`radar`, `axis-variants`, `named-range`, `barley-trellis`) | Marks with `zindex: 0` paint first in specification order, then the rest sorted by `zindex` and declaration. That is upstream's rule and not the obvious one: a **negative** `zindex` raises a mark above its neighbours rather than sinking it, because `zorder` partitions on `if (item.zindex)` instead of sorting the whole list. Encoding order is unchanged — a mark reading back another mark's items still needs it built first. Per-*item* `zindex`, from an encode channel, is still reported | 3 |
| A mark drawn from a **group** mark | **Supported** | `FixtureDifferentialTest` (`barley-trellis`) | The same namespace, and the item is the group's own encoded channels plus `datum` — its facet tuple. That is how a trellis titles each cell: a text mark drawn from the group reads `width` for the centre, `y` for the row and `datum.site` for the name, none of which any dataset holds. A group placed by a `layout` reports the position it encoded rather than the one the grid gave it, which is a known difference and the only case where the two disagree | 3 |
| Guide `encode`: a legend label read through a scale | **Supported** | `FixtureDifferentialTest` (`global-development`) | `encode.labels.update.text` with `{"scale": "label", "field": "value"}` — how a cluster's id becomes its name, resolved against the entry as its datum. There is no `legendLabelText` property to fold that into, and `symbols.*.fillOpacity` is the same case: upstream's `symbolOpacity` fades the outline with the swatch, and this fades only what is inside it | 5 |
| Guide `encode`: a label's own position | **Supported** | `FixtureDifferentialTest` (`budget-forecasts`) | `encode.labels.update.x` resolved against the tick as its datum, so `{"scale": "x", "field": "value"}` moves every label to the start of its band. **`update` only**: a guide writes its own text and position into `update` on every pass, so a specification's `enter` is overwritten before anything is drawn — verified upstream, where a label given `enter: {text: ...}` still reads its tick's own text. An `enter` block naming one of those is reported as changing nothing rather than as unimplemented, because the rule is Vega's and not this engine's | 5 |
| Guide `encode` blocks | **Partial** | `AxisStyleTest`, `FixtureDifferentialTest` (`barley-trellis`) | An axis's `grid`, `ticks`, `domain`, `labels` and `title` blocks, and a legend's `symbols`, `labels` and `title`, folded into the properties they are another spelling of — `encode.grid.enter.strokeDash` **is** `gridDash` upstream, which builds each part from an encode block and extends it with the specification's. Folding rather than overlaying is what makes the block participate in *measurement*: a legend symbol resized through `encode` moves every label beside it. Only constants fold; a `signal`, a `field` or a conditional needs the guide's own datum, which does not exist until the guide is laid out, and each is reported by name along with any part or channel with no property behind it | 5 |
| Group scopes (nested `data`, `signals`, `scales`, `axes`, `marks`) | **Supported** | `GroupMarkTest` | A nested definition shadows a same-named one outside. Two upstream behaviours are reproduced rather than corrected: `parent` is the group's datum, not the group item, so `parent.width` is undefined; and `width`/`height` are inherited, so a nested `"height"` range spans the whole chart unless the group declares its own `height` signal | 3 |
| Axis `offset` and its gridlines | **Supported** | `FixtureDifferentialTest` (`qq-plot`) | An `offset` moves the axis away from the plot and the gridlines **back**: upstream gives every gridline endpoint an offset of `sign * axis.offset`, cancelling the translation the axis group carries. Without it a gridline is dragged along with its axis and floats clear of the data it measures | 5 |
| Group `layout` (the trellis grid) | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`trellis-layout`) | Automatic row and column placement with per-direction padding, at the top level or on a group. Every cell in the scope goes on **one** grid whichever group mark produced it, which looks the same whenever there is only one — as every trellis fixture had — and is the difference between two side-by-side plots and two plots on top of each other. Cells are measured by how far their contents reach, not by their declared size, so a trellis whose axis labels hang off to the left leaves room for them. `align`, `bounds`, `center` and footers are reported | 5 |
| Rect | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` | Encoder handles x/x2/width and y/y2/height pairs, band offsets, fill, stroke, opacity, corner radius. A mark that encodes **either** paint channel gets neither default, as upstream does, so a rect given only a stroke draws as a hollow outline rather than picking up the built-in blue. Geometry matches upstream exactly on the bar fixture | 3 |
| Rule | **Supported** | `SpecCompilerTest` | A missing `x2`/`y2` defaults to `x`/`y`, as upstream. Bounds expand on both axes, which is what upstream does too — verified on `stack-diverging`, where a 1-unit rule spanning the plot bounds to half a unit past each end | 3 |
| Mark stroke style | **Supported** | `FixtureDifferentialTest` (`legend-style`) | `strokeDash`, `strokeCap` and `strokeJoin` as encode channels. A dash pattern with a negative or non-finite entry is dropped rather than half-applied, because SVG and Canvas disagree about what such a pattern draws. `strokeDashOffset`, `strokeMiterLimit` and `strokeOffset` are reported | 5 |
| Line | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`line-area`, `area-gaps`, `curves`, `curves-closed`) | One `PathNode` per series where upstream emits one item per datum; the harness normalizes both to a point list. A `null` in the data does **not** break the line — upstream reads the coordinate as `item.y \|\| 0` and draws through zero — and the `defined` channel is what breaks it. A line is stroked by default but is **also filled** when the mark encodes a `fill`, which is what shades the inside of a closed radar polygon. Twelve interpolation methods are implemented: `linear`, the step family, `basis`, `cardinal`, `monotone` and `natural`, and the closed variants `linear-closed`, `basis-closed` and `cardinal-closed`, all ported from d3-shape. `monotone` is two curves — Vega picks d3's X or Y form from the mark's `orient` — so a horizontal series is monotone in *y*. The closed splines are not the open ones with a `Z` on the end: they wrap their control-point window round the join and emit no `Z` at all past two points. `catmull-rom` and `bundle` carry their own parameterisation and are reported, not approximated | 3 |
| Area | **Supported** | `FixtureDifferentialTest` (`line-area`, `area-gaps`) | Both orientations, via the (x, y) and (x2, y2) boundary pairs, and a band between two data fields rather than a baseline. Stacking comes from the `stack` transform. `defined` and interpolation as for `line` | 3 |
| Symbol | **Supported** | `SceneNodeTest`, `FixtureDifferentialTest` (`log-scale` fixture) | All 12 of upstream's shapes, pinned by reference vectors. Sized upstream's way, from `sqrt(size) / 2`, **not** d3-shape's area convention — the two differ by 13% on a circle. A `shape` that is not one of the twelve names is read as an SVG path string, written in a unit box and scaled by the same reference length, so a custom outline sizes with `size` exactly as a built-in one does | 3 |
| Text | **Supported** | `FixtureDifferentialTest` (`line-area` fixture) | Align, baseline, font, size, weight, style, angle and `dx`/`dy`. Metrics are platform metrics, not browser metrics | 3 |
| Arc | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`pie`) | Annular sectors, so pie and donut charts draw. Angles run clockwise from twelve o'clock. `padAngle`, `padRadius` and `cornerRadius` are d3-shape's own geometry, ported. Neither is what its name suggests: a pad angle is a gap measured at a pad **radius** and converted back to an angle separately for each edge, so the sides of a gap stay parallel rather than splaying; and a corner radius is clamped by where the slice's own edges would meet, so a thin slice rounds less than a fat one and one too small to round loses its corners rather than folding inside out | 5 |
| Image | **Supported** | `FixtureDifferentialTest` (`image-marks`), `ImageMarkInstrumentedTest` (on an API 37 emulator) | `align` and `baseline` move the **whole image** rather than text inside a box, so `x` is its left edge, middle or right edge — the opposite of `rect`, where `x` is always the left edge. They are held on the node and applied at paint time, as upstream does, so the scene keeps the `x` the specification gave and two images at different anchors stay distinguishable. `aspect` (default true) letterboxes; `false` stretches. A `width` or `height` left out is taken from the image's own pixels upstream, which the compiler cannot know — the mark is placed with a zero extent and that is reported. An unresolvable URL leaves a gap **and a diagnostic**, never a silent one | 5 |
| Arc | Planned | — | — | 3 |
| Path (from SVG path strings) | **Supported** | `FixtureDifferentialTest` (`path-marks`) | The whole SVG path grammar, including implicit repeated commands — where a repeated `M` means `L` — numbers run together without separators, the `S`/`T` control-point reflections, and the elliptical arc converted from its endpoint form. The outline is in its own coordinates and the mark's `x`/`y` place it, with `scaleX`, `scaleY` and `angle` transforming it about that anchor. A string that cannot be read through stops where the reading did and is reported | 3 |
| Trail | **Supported** | `FixtureDifferentialTest` (`trail`) | A **filled** run of capsules, one per segment, overlapping at the shared points — not a stroke, since a stroke has one width. Its `size` is a **width**, halved to a radius, where a symbol's is a squared extent. Compared by the extent it covers rather than by its outline: the caps are semicircles, so this engine's cubics and upstream's true arcs differ in the last decimals, the same way an arc's do | 5 |
| Shape (geo) | Not planned | — | Needs projections, an explicit non-goal | — |

## Scales

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| Linear | **Supported** | `ScalesTest`, `TicksTest`, `FixtureDifferentialTest` | Domain, range, ticks and `nice` match d3 and upstream exactly. See the `zero` row below for when it widens to the origin — it is not what "data-driven" suggests | 3 |
| `round` on a continuous scale | **Supported** | `FixtureDifferentialTest` (`grouped-bar`) | Rounds every *output* to a whole unit, so a bar's edge lands on a pixel. Not the same `round` a band scale has, which rounds the step and the band width and so moves where every band starts: here nothing about the scale changes. Upstream cannot call `round` on a continuous d3 scale — there is no such method — so it swaps the range interpolator for `interpolateRound`, which is why `invert()` still reads back the unrounded value. It had been parsed and dropped for every continuous type, silently, leaving every bar in the chart a fraction of a unit wide | 3 |
| `reverse` | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`band-padding`) | Flips the **range**, leaving the domain alone, for every scale type. Reversing the domain instead maps every value to the same place, so the chart looks right and the ticks, labels and domain line all come out backwards | 3 |
| Time, UTC | **Supported** | `TimeScaleTest`, `FixtureDifferentialTest` (`time-axis`) | Ticks land on calendar boundaries from d3's own table; `nice` widens to one of them; each label is written at its own granularity, so a monthly axis reads "2026" every January and "February" otherwise. A day is a calendar day, so a daily tick holds midnight across a daylight-saving change. Locales and explicit axis format strings are not implemented | 6 |
| Reading dates | **Supported** | `TimeScaleTest`, `SpecCompilerTest` | `format.parse` with `date`, `number`, `string` and `boolean`. ISO 8601 only: a bare date is UTC and one carrying a wall-clock time is local, matching JavaScript. Anything else is reported rather than guessed at, because upstream falls back to the host's parser and that differs between browsers | 6 |
| Discrete domain `sort` | **Supported** | `DomainSortTest` (upstream vectors), `FixtureDifferentialTest` (`sorted-domain`) | Both forms: by the domain value, and by an aggregate of a field the domain never mentions — which is how a bar chart is ordered by a total no row carries. Upstream *groups* the dataset on the domain field rather than listing its values, so the default order is first appearance, an aggregate sort has a grouping to ride on, and ties hold their group order. An object naming neither `op` nor `field` sorts by the value, so `{"order": "descending"}` is the only spelling of a reverse-alphabetical domain; a `field` with no `op` names an aggregate output that was never computed and changes nothing, which is reproduced and reported. A domain over several fields runs field by field, and accepts only `count`, `min` and `max`, being the operations that survive folding twice | 5 |
| `scale()` and `invert()` in an expression | **Supported** | `ScaleExpressionTest`, `FixtureDifferentialTest` (`bin-to-ordinal`) | How a specification positions something *between* two scaled values — a label at a bin's midpoint, a rule at the middle of a band — which no encoding channel can say, since a channel scales one field and stops. Available to mark encodings, axes and legends; **not** to a signal's own `update` in the *same* scope, because a scale there is built *from* those signals; a **group's** signals may read the enclosing scope's scales, which were built long before the group was reached, and that is how a trellis cell takes its height from one band of the outer scale. Reported with the reason rather than resolving to null, and the three failures are told apart: asked too early in this scope, asked too early at the top level, and no such scale. `invert()` needs a continuous scale; a discrete one maps many positions to one value and is reported. Upstream's third argument, selecting a scale from another group's scope, has no equivalent here and is reported | 4 |
| A data-driven scale **range** | **Supported** | `ScaleResolver` | `{"data": "clusters", "field": "name"}` — the mirror of a data-driven domain, and how an ordinal scale becomes a lookup table the data itself defines: `id` in, `name` out, both read from the same rows. Distinct values in first-seen order, so a domain read the same way from the same rows lines up entry for entry | 4 |
| A signal-valued data `url` | **Supported** | `DataResolver` | `{"url": {"signal": "..."}}`, which is how a control chooses the file a chart reads. Resolved when the data is, so the signal has to be one that does not itself depend on data — the same rule every other pre-data signal follows. An address that resolves to nothing is named rather than fetched blindly | 4 |
| A channel holding a Vega null | **Supported** | `FixtureDifferentialTest` (`donut-chart-labelled`) | Resolves to *nothing*, not to the four letters that spell it. Upstream's `textValue` is `line == null ? '' : (line + '').trim()`, so a text mark with no text draws nothing and a trailing space is trimmed before measuring. Stringifying the null instead printed "null" wherever a label was empty — which no mark comparison can see, because a text mark is compared by its anchor rather than its content | 6 |
| A stroke on an invisible mark | **Supported** | `FixtureDifferentialTest` (`donut-chart-labelled`) | Does not widen the mark's bounds. Upstream's `boundStroke` tests the **item's** own opacity as well as the stroke's, so a mark at `opacity: 0` reaches exactly as far as its geometry. It shows wherever an invisible mark sits at the edge of a chart — a layout laid out with debug rectangles left switched off enlarged the surface by the width of a stroke nobody could see | 6 |
| A mark that names no position at all | **Supported** | `FixtureDifferentialTest` (`crossfilter-flights`) | The origin, not a reason to drop the mark: upstream reads `item.x || 0` in every mark's draw path, so a heading written as `{"y": -5}` and nothing else is drawn hard against the left of the group it is in. `text` and `symbol` dropped such a mark silently; every other encoder already defaulted this way. Distinct from the row below, which is about a channel that *is* declared and resolves to nothing | 6 |
| A mark channel that resolves to nothing | **Supported** | `FixtureDifferentialTest` (`interactive-legend`) | A channel the specification *declares* whose value comes back null leaves the mark in the scene with a zero extent, painting nothing — which is what upstream does, where the scene property is simply never set. A brush `rect` positioned from a signal that is empty until someone drags depends on it: the item has to exist to be dragged. A channel the specification names nowhere is still a malformed mark and still reported | 6 |
| Legend `encode` with a conditional rule | **Supported** | `FixtureDifferentialTest` (`interactive-legend`) | A legend swatch's `opacity` resolved against the entry it is drawing, so `[{test: ..., value: 0.7}, {value: 0.15}]` dims the series that are not selected. `symbolOpacity` says the same thing as a constant and cannot express a rule, which is why the `encode` block wins | 5 |
| Scale `bins` | **Supported** | `FixtureDifferentialTest` (`histogram-null-values`) | The boundaries a scale's ticks land on, written out, described as `{start, stop, step}`, or held in a signal — which is the form the `bin` transform publishes. `start` is pulled up to the first whole step inside the domain and `stop` down to the last, so a binning computed over a wider extent than the axis shows does not hang ticks off either end. Setting it also drops the `zero` a linear, pow or sqrt scale would otherwise include, which is upstream's `includeZero` test and not obvious from the documentation. The boundaries are never thinned, because upstream raises the tick count to their number first | 4 |
| A scale domain's `field` from a signal | **Supported** | `FixtureDifferentialTest` (`time-units`) | `{"data": "flights", "field": {"signal": "measure"}}` — the *name* of the column comes from a control, which is how a chart offers a measure picker over one scale. Upstream's `Scope.fieldRef` takes a string or a signal here and errors on anything else, and the signal supplies the name, so it is **one** lookup and not the two the same object makes under a mark's `field`. It is also an edge in the dependency order: the scale cannot be built before the signal that names its column. The other reference forms need a datum or an enclosing group, neither of which exists where a scale is built, and are reported | 4 |
| Signal-valued scale domain | **Supported** | `FixtureDifferentialTest` (`expressions` fixture) | `{"domain": {"signal": "..."}}`, which is how a specification points a scale at what the `extent` transform published. A signal that produces nothing is reported rather than defaulted to `[0, 1]` | 4 |
| Band | **Supported** | `ScalesTest`, `FixtureDifferentialTest` | Step, bandwidth, padding, align and round match d3-scaleBand exactly | 3 |
| Point | **Supported** | `ScalesTest` | Implemented as a band scale with paddingInner 1, as d3 does | 3 |
| Ordinal | **Supported** | `ScalesTest` | Explicit range arrays only; colour schemes report `VEGA_SCALE_UNSUPPORTED_TYPE` | 3 |
| Log | **Supported** | `TransformedScalesTest`, `FixtureDifferentialTest` | Configurable base; a domain spanning or touching zero is reported rather than adjusted. Ticks are the powers and their multiples, falling back to linear spacing when that is too sparse, and crowded labels are blanked as d3 does | 3 |
| Pow, sqrt | **Supported** | `TransformedScalesTest` | `pow` defaults to exponent 1, i.e. linear, as upstream; `sqrt` is exponent 0.5. Negative domains handled by sign | 3 |
| Symlog | **Supported** | `TransformedScalesTest` | `sign(x) * ln(1 + abs(x) / constant)`; handles zero and both signs | 3 |
| Sequential colour | **Supported** | `ColorScaleTest`, `FixtureDifferentialTest` | An explicit colour range interpolated in RGB or Lab, clamped at both ends as upstream does | 3 |
| Categorical colour schemes | **Supported** | `ColorScaleTest`, `FixtureDifferentialTest` | 15 palettes, values read out of `vega.scheme()` so they are exact: category10/20/20b/20c, tableau10/20, accent, dark2, paired, pastel1/2, set1/2/3, observable10 |
| Scheme forms (`{"scheme": …}`) | **Supported** | `FixtureDifferentialTest` (`scheme-forms`) | All three upstream accepts: a name, a signal holding a name — how a chart offers a palette picker — and the stops written out inline, which is a scheme in every respect except that nobody named it.
