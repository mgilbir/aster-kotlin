# Supported features

Statuses: **Supported** · **Partial** · **Planned** · **Not planned** · **Blocked**

"Tests" names the test class or golden that covers the row. An unsupported construct always produces a
structured diagnostic; nothing is silently ignored (PROJECT_BRIEF.md 3.3, 14).

**Read the Marks table carefully.** A row says "Supported" only when the engine can *produce* that
construct from an input specification. Where a scene node type exists but nothing encodes data into it
yet, the row says **Renderable** — the geometry draws and hit-tests correctly, but there is no mark
encoder, so a Vega specification cannot ask for it. Six of the twelve mark types are now Supported; see
the scope note in STATUS.md for how much of upstream Vega remains.

| Generic JSON value model | Supported | `VegaValueTest`, `JsonBridgeTest` | Numbers are always `Double` | 0 |
| Dotted / bracketed field paths | Supported | `VegaValueTest` | Malformed paths resolve to null rather than throwing | 0 |
| `config` blocks | **Partial** | `ConfigTest` (upstream vectors), `FixtureDifferentialTest` (`config-theme`, `config-marks`) | The guide blocks: `axis` with its `axisX`/`axisY`, `axisTop`/`axisBottom`/`axisLeft`/`axisRight` and `axisBand` variants, `legend`, the `guide-label` and `guide-title` styles, and `background`/`padding`/`autosize`. Precedence runs style → axis → dimension → side → band → the guide's own properties, verified by setting one property at every level and seeing which drew. | Unhandled properties reported | **Supported** | `UnhandledPropertiesTest` | Each parser names the properties it *consumes* and reports the remainder, rather than keeping a list of what is missing. Covers axes, scales, legends, titles, marks and encode channels, so a property nobody anticipated — including one upstream adds later — is a diagnostic rather than a silence. Where there is something specific to say about what gets drawn instead, it is said by name: `limit`, for instance, draws the text past the width it was told to stay inside | 5 |

## Marks

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| Group | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`facet-trellis` fixture) | One container per datum, translated by its `x`/`y`, painting its fill and stroke over its declared `width` × `height`. `clip` narrows it. Nests to any depth | 3 |
| Faceting (`from.facet`) | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`facet-trellis` fixture) | `groupby` only, on one or more fields. Cells appear in first-appearance order and each cell's datum is the groupby fields plus `count`, matching the `aggregate` transform upstream inserts. Pre-faceted `facet.field` and extra `facet.aggregate` measures are reported | 3 |
| Group scopes (nested `data`, `signals`, `scales`, `axes`, `marks`) | **Supported** | `GroupMarkTest` | A nested definition shadows a same-named one outside. Two upstream behaviours are reproduced rather than corrected: `parent` is the group's datum, not the group item, so `parent.width` is undefined; and `width`/`height` are inherited, so a nested `"height"` range spans the whole chart unless the group declares its own `height` signal | 3 |
| Group `layout` (the trellis grid) | **Supported** | `GroupMarkTest`, `FixtureDifferentialTest` (`trellis-layout`) | Automatic row and column placement with per-direction padding, at the top level or on a group. Cells are measured by how far their contents reach, not by their declared size, so a trellis whose axis labels hang off to the left leaves room for them. `align`, `bounds`, `center` and footers are reported | 5 |
| Rect | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` | Encoder handles x/x2/width and y/y2/height pairs, band offsets, fill, stroke, opacity, corner radius. A mark that encodes **either** paint channel gets neither default, as upstream does, so a rect given only a stroke draws as a hollow outline rather than picking up the built-in blue. Geometry matches upstream exactly on the bar fixture | 3 |
| Rule | **Supported** | `SpecCompilerTest` | A missing `x2`/`y2` defaults to `x`/`y`, as upstream. Bounds expand on both axes, which is what upstream does too — verified on `stack-diverging`, where a 1-unit rule spanning the plot bounds to half a unit past each end | 3 |
| Mark stroke style | **Supported** | `FixtureDifferentialTest` (`legend-style`) | `strokeDash`, `strokeCap` and `strokeJoin` as encode channels. A dash pattern with a negative or non-finite entry is dropped rather than half-applied, because SVG and Canvas disagree about what such a pattern draws. `strokeDashOffset`, `strokeMiterLimit` and `strokeOffset` are reported | 5 |
| Line | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`line-area`, `area-gaps`) | One `PathNode` per series where upstream emits one item per datum; the harness normalizes both to a point list. A `null` in the data does **not** break the line — upstream reads the coordinate as `item.y \|\| 0` and draws through zero — and the `defined` channel is what breaks it. Nine interpolation methods are implemented: `linear`, the step family, and `basis`, `cardinal`, `monotone` and `natural`, ported from d3-shape. `monotone` is two curves — Vega picks d3's X or Y form from the mark's `orient` — so a horizontal series is monotone in *y*. `catmull-rom` and `bundle` carry their own parameterisation and closed variants and are reported, not approximated | 3 |
| Area | **Supported** | `FixtureDifferentialTest` (`line-area`, `area-gaps`) | Both orientations, via the (x, y) and (x2, y2) boundary pairs, and a band between two data fields rather than a baseline. Stacking comes from the `stack` transform. `defined` and interpolation as for `line` | 3 |
| Symbol | **Supported** | `SceneNodeTest`, `FixtureDifferentialTest` (`log-scale` fixture) | All 12 of upstream's shapes, pinned by reference vectors. Sized upstream's way, from `sqrt(size) / 2`, **not** d3-shape's area convention — the two differ by 13% on a circle. A `shape` that is not one of the twelve names is read as an SVG path string, written in a unit box and scaled by the same reference length, so a custom outline sizes with `size` exactly as a built-in one does | 3 |
| Text | **Supported** | `FixtureDifferentialTest` (`line-area` fixture) | Align, baseline, font, size, weight, style, angle and `dx`/`dy`. Metrics are platform metrics, not browser metrics | 3 |
| Arc | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`pie`) | Annular sectors, so pie and donut charts draw. Angles run clockwise from twelve o'clock. `padAngle`, `padRadius` and `cornerRadius` are d3-shape's own geometry, ported. Neither is what its name suggests: a pad angle is a gap measured at a pad **radius** and converted back to an angle separately for each edge, so the sides of a gap stay parallel rather than splaying; and a corner radius is clamped by where the slice's own edges would meet, so a thin slice rounds less than a fat one and one too small to round loses its corners rather than folding inside out | 5 |
| Image | **Supported** | `FixtureDifferentialTest` (`image-marks`), `ImageMarkInstrumentedTest` (on an API 37 emulator) | `align` and `baseline` move the **whole image** rather than text inside a box, so `x` is its left edge, middle or right edge — the opposite of `rect`, where `x` is always the left edge. They are held on the node and applied at paint time, as upstream does, so the scene keeps the `x` the specification gave and two images at different anchors stay distinguishable. `aspect` (default true) letterboxes; `false` stretches. A `width` or `height` left out is taken from the image's own pixels upstream, which the compiler cannot know — the mark is placed with a zero extent and that is reported. An unresolvable URL leaves a gap **and a diagnostic**, never a silent one | 5 |
| Arc | Planned | — | — | 3 |
| Path (from SVG path strings) | **Supported** | `FixtureDifferentialTest` (`path-marks`) | The whole SVG path grammar, including implicit repeated commands — where a repeated `M` means `L` — numbers run together without separators, the `S`/`T` control-point reflections, and the elliptical arc converted from its endpoint form. The outline is in its own coordinates and the mark's `x`/`y` place it, with `scaleX`, `scaleY` and `angle` transforming it about that anchor. A string that cannot be read through stops where the reading did and is reported | 3 |
| Trail | **Supported** | `FixtureDifferentialTest` (`trail`) | A **filled** run of capsules, one per segment, overlapping at the shared points — not a stroke, since a stroke has one width. Its `size` is a **width**, halved to a radius, where a symbol's is a squared extent. Compared by the extent it covers rather than by its outline: the caps are semicircles, so this engine's cubics and upstream's true arcs differ in the last decimals, the same way an arc's do | 5 |
| Shape (geo) | Not planned | — | Needs projections, an explicit non-goal | — |

## Scales

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| Linear | **Supported** | `ScalesTest`, `TicksTest`, `FixtureDifferentialTest` | Domain, range, ticks and `nice` match d3 and upstream exactly. See the `zero` row below for when it widens to the origin — it is not what "data-driven" suggests | 3 |
| `reverse` | **Supported** | `SpecCompilerTest`, `FixtureDifferentialTest` (`band-padding`) | Flips the **range**, leaving the domain alone, for every scale type. Reversing the domain instead maps every value to the same place, so the chart looks right and the ticks, labels and domain line all come out backwards | 3 |
| Time, UTC | **Supported** | `TimeScaleTest`, `FixtureDifferentialTest` (`time-axis`) | Ticks land on calendar boundaries from d3's own table; `nice` widens to one of them; each label is written at its own granularity, so a monthly axis reads "2026" every January and "February" otherwise. A day is a calendar day, so a daily tick holds midnight across a daylight-saving change. Locales and explicit axis format strings are not implemented | 6 |
| Reading dates | **Supported** | `TimeScaleTest`, `SpecCompilerTest` | `format.parse` with `date`, `number`, `string` and `boolean`. ISO 8601 only: a bare date is UTC and one carrying a wall-clock time is local, matching JavaScript. Anything else is reported rather than guessed at, because upstream falls back to the host's parser and that differs between browsers | 6 |
| Discrete domain `sort` | **Supported** | `DomainSortTest` (upstream vectors), `FixtureDifferentialTest` (`sorted-domain`) | Both forms: by the domain value, and by an aggregate of a field the domain never mentions — which is how a bar chart is ordered by a total no row carries. Upstream *groups* the dataset on the domain field rather than listing its values, so the default order is first appearance, an aggregate sort has a grouping to ride on, and ties hold their group order. An object naming neither `op` nor `field` sorts by the value, so `{"order": "descending"}` is the only spelling of a reverse-alphabetical domain; a `field` with no `op` names an aggregate output that was never computed and changes nothing, which is reproduced and reported. A domain over several fields runs field by field, and accepts only `count`, `min` and `max`, being the operations that survive folding twice | 5 |
| `scale()` and `invert()` in an expression | **Supported** | `ScaleExpressionTest`, `FixtureDifferentialTest` (`bin-to-ordinal`) | How a specification positions something *between* two scaled values — a label at a bin's midpoint, a rule at the middle of a band — which no encoding channel can say, since a channel scales one field and stops. Available to mark encodings, axes and legends; **not** to a signal's own `update` in the *same* scope, because a scale there is built *from* those signals; a **group's** signals may read the enclosing scope's scales, which were built long before the group was reached, and that is how a trellis cell takes its height from one band of the outer scale. Reported with the reason rather than resolving to null, and the three failures are told apart: asked too early in this scope, asked too early at the top level, and no such scale. `invert()` needs a continuous scale; a discrete one maps many positions to one value and is reported. Upstream's third argument, selecting a scale from another group's scope, has no equivalent here and is reported | 4 |
| Signal-valued scale domain | **Supported** | `FixtureDifferentialTest` (`expressions` fixture) | `{"domain": {"signal": "..."}}`, which is how a specification points a scale at what the `extent` transform published. A signal that produces nothing is reported rather than defaulted to `[0, 1]` | 4 |
| Band | **Supported** | `ScalesTest`, `FixtureDifferentialTest` | Step, bandwidth, padding, align and round match d3-scaleBand exactly | 3 |
| Point | **Supported** | `ScalesTest` | Implemented as a band scale with paddingInner 1, as d3 does | 3 |
| Ordinal | **Supported** | `ScalesTest` | Explicit range arrays only; colour schemes report `VEGA_SCALE_UNSUPPORTED_TYPE` | 3 |
| Log | **Supported** | `TransformedScalesTest`, `FixtureDifferentialTest` | Configurable base; a domain spanning or touching zero is reported rather than adjusted. Ticks are the powers and their multiples, falling back to linear spacing when that is too sparse, and crowded labels are blanked as d3 does | 3 |
| Pow, sqrt | **Supported** | `TransformedScalesTest` | `pow` defaults to exponent 1, i.e. linear, as upstream; `sqrt` is exponent 0.5. Negative domains handled by sign | 3 |
| Symlog | **Supported** | `TransformedScalesTest` | `sign(x) * ln(1 + abs(x) / constant)`; handles zero and both signs | 3 |
| Sequential colour | **Supported** | `ColorScaleTest`, `FixtureDifferentialTest` | An explicit colour range interpolated in RGB or Lab, clamped at both ends as upstream does | 3 |
| Categorical colour schemes | **Supported** | `ColorScaleTest`, `FixtureDifferentialTest` | 15 palettes, values read out of `vega.scheme()` so they are exact: category10/20/20b/20c, tableau10/20, accent, dark2, paired, pastel1/2, set1/2/3, observable10 |
| Scheme forms (`{"scheme": …}`) | **Supported** | `FixtureDifferentialTest` (`scheme-forms`) | All three upstream accepts: a name, a signal holding a name — how a chart offers a palette picker — and the stops written out inline, which is a scheme in every respect except that nobody named it. The name is lowercased before lookup, as `vega-encode` does, so a picker offering "Viridis" finds `viridis`. `count` truncates the palette for the discretizing scales but **not** for an ordinal one, which keeps the whole palette and cycles: upstream's rule, and truncating there repeats the first colours instead of reaching the later ones | 5 |
| Continuous colour ramps (`viridis`, `blues`, …) | **Supported** | `ColorScaleTest`, `FixtureDifferentialTest` (`colour-ramps`) | All 53 of them. They are **Vega's own tables, not d3's** — `blues` starts at `#cfe1f2`, a fifth of the way into d3's `interpolateBlues`, which looked like a scale-level extent of `[0.2, 1]` applied over d3's ramp and is not: the table simply starts there and nothing narrows it. Once the table is right the interpolation is plain piecewise RGB, which the sequential colour scale already did | 5 |
| Colour interpolation spaces | Partial | `ColorScaleTest` | `rgb` and `lab`. `hcl`, `hsl` and `cubehelix` fall back to RGB with a diagnostic | 5 |
| Quantize | **Supported** | `BinnedScaleTest` (upstream vectors), `FixtureDifferentialTest` (`binned-scales`) | Equal-width intervals of the domain, so a skewed column crowds into one bucket. Cut points are computed in d3's own form rather than accumulated, so they do not drift across a wide domain | 6 |
| Quantile | **Supported** | `BinnedScaleTest` (upstream vectors), `FixtureDifferentialTest` (`binned-scales`) | Equal-**count** buckets, cut at the quantiles of the domain itself — which is why its domain is the whole column and not its extent, and why duplicates are kept: dropping one would move every quartile | 6 |
| Threshold | **Supported** | `BinnedScaleTest` (upstream vectors), `FixtureDifferentialTest` (`binned-scales`) | The domain *is* the cut points, so there is one more range value than domain value. A mismatched count is reported rather than silently truncated | 6 |
| Bin-ordinal | **Supported** | `BinnedScaleTest` (upstream vectors), `FixtureDifferentialTest` (`binned-scales`) | The domain is bin edges and the bucket indexes an **ordinal** range, so it wraps: a fifth bin reuses the first colour rather than running out. A value below the first edge maps to nothing at all, unlike the other three | 6 |
| Where a boundary value lands | **Supported** | `BinnedScaleTest` | All four bisect **right**, so a value sitting exactly on a cut point falls into the bucket *above* it. Easy to get backwards and invisible until a boundary value turns up in the data | 6 |
| `domainMin`, `domainMax`, `domainMid` | **Supported** | `DomainLimitsTest` (upstream vectors), `FixtureDifferentialTest` (`domain-limits`) | They **replace** an end of the resolved domain rather than clamping it, and run after `zero` — so `domainMin: 30` beats the zero that would otherwise have pulled the domain down, and a minimum placed above the maximum is left running backwards, as upstream leaves it. `nice` runs last, over whatever the limits produced. Either may come from a signal | 6 |
| `zero` | **Supported** | `DomainLimitsTest` | Follows the **scale type**, through upstream's `includeZero`: linear, pow and sqrt, and nothing else — not log, not symlog, and not a linear scale with a colour range, which upstream turns into `sequential-linear`. Not about whether the domain came from the data: a linear scale handed `[10, 20]` still starts at 0 | 3 |
| `domainRaw`, `domainImplicit`, `bins` | Not implemented | `UnhandledPropertiesTest` | Three of upstream's 23 scale properties, each reported by name | 6 |

## Data transforms

Upstream Vega has 40 transforms; the 12 the brief lists for the first release are implemented, plus `timeunit`, `pie`, `window`, `sequence`, `lookup`, `impute`, `cross`, `pivot`, `countpattern`, the whole statistical family — `quantile`, `regression`, `loess`, `kde`, `density`, `dotbin` — the whole hierarchy family: `stratify`, `nest`, `treemap`, `partition`, `pack` and `tree`, and the two that draw the edges between a tree's nodes: `treelinks` and `linkpath`.
Expected values in `TransformReferenceTest` were all generated from upstream.

| Feature | Status | Tests | Known differences | Target milestone |
| --- | --- | --- | --- | --- |
| `filter` | **Supported** | `TransformReferenceTest` | A broken expression leaves the data alone rather than dropping every row | 4 |
| `formula` | **Supported** | `TransformReferenceTest` | — | 4 |
| `collect` | **Supported** | `TransformReferenceTest` | Missing values sort first ascending, as upstream; multi-field with per-field order | 4 |
| `project` | **Supported** | `TransformReferenceTest` | — | 4 |
| `identifier` | **Supported** | `TransformReferenceTest` | Numbers from 1 per pipeline, not per view, so ids are reproducible but not globally unique | 4 |
| `extent` | **Supported** | `TransformReferenceTest` | Publishes a signal; missing values excluded | 4 |
| `aggregate` | **Supported** | `TransformReferenceTest` | 17 ops. `count` counts tuples while `valid` counts values; `variance`/`stdev` are the sample forms | 4 |
| `joinaggregate` | **Supported** | `TransformReferenceTest` | — | 4 |
| `bin` | **Supported** | `TransformReferenceTest` | Step algorithm ported from vega-statistics; out-of-extent values get null bounds. Deriving a missing `extent` from the data is an addition upstream does not make, and is reported | 4 |
| `stack` | **Supported** | `TransformReferenceTest` | `zero`, `center` and `normalize`; negatives stack away from zero; `sort` reorders stacking only | 4 |
| `fold` | **Supported** | `TransformReferenceTest` | — | 4 |
| `flatten` | **Supported** | `TransformReferenceTest` | Parallel fields flatten together; empty arrays drop the row | 4 |
| `timeunit` | **Supported** | `TimeUnitTransformTest` (upstream vectors), `FixtureDifferentialTest` (`timeunit`) | Buckets a date into the calendar period the listed units describe, emitting the bucket start and the next one. The floor is *built* from the units present, so omitting the year deliberately collapses every January onto one bucket — a seasonal profile rather than a timeline. `week`, `day` and `dayofyear` need week numbering and are reported; so is inferring the units from the data | 6 |
| `pie` | **Supported** | `FixtureDifferentialTest` (`pie`) | Turns a column of numbers into start and end angles. Absolute values are taken, because a negative slice would run backwards over its neighbour rather than shrinking; with no `field` every row gets an equal share | 5 |
| `window` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`window`) | Running totals, ranks and moving averages. The ranking family — `row_number`, `rank`, `dense_rank`, `percent_rank`, `cume_dist`, `ntile`, `lag`, `lead`, `first_value`, `last_value`, `nth_value`, `prev_value`, `next_value` — looks at the whole partition and ignores the frame; the aggregate family respects it. The frame defaults to `[null, 0]`, the partition start up to and including this row, which is what makes a bare `sum` a running total rather than a partition total. With a `sort` and without `ignorePeers` the frame widens to cover tying rows, so two rows that compare equal always get the same answer | 6 |
| `sequence` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`sequence-lookup`) | Generates rows rather than reading them, so it replaces whatever reached it and is only ever a pipeline's first stage. `stop` is **exclusive** — `{start: 0, stop: 5}` is five rows — and the field is named `data` unless `as` says otherwise. Steps are multiplied out from the start rather than accumulated, so a fractional step does not drift | 6 |
| `lookup` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`sequence-lookup`) | With `values`, the named fields are copied out of the matched row and `as` renames them; without `values`, the whole matched row goes into the one field `as` names. An unmatched row takes `default`, or null. A duplicated key in the lookup table resolves to the **last** row carrying it, as a map built by insertion does | 6 |
| `impute` | **Supported** | `TransformReferenceTest` (upstream vectors) | Adds the rows a series is missing so a line does not jump the gap. The key domain is the union across the **whole dataset**, not per group — a group is missing a key precisely when another group has it — and `keyvals` replaces that domain, so a series can be padded past where its data reached. `method` is `value` (the default, with a value of 0) or any aggregate, computed over the group's existing rows. New rows are **appended** rather than merged into position, and carry only the group's fields, the key and the filler | 6 |
| `cross` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`reshape-matrix`) | Every row paired with every row. Each output row holds the two originals **whole**, under `a` and `b` unless `as` renames them — not their fields merged, which would lose a column whenever both sides share a name — so an expression reaching into one writes `datum.a.value`. `filter` is applied as the pairs form, which is how a specification takes half a matrix | 6 |
| `pivot` | **Supported** | `TransformReferenceTest` (upstream vectors) | Turns rows into columns. The names come from the data and are sorted **alphabetically** before `limit` takes the first few, so limiting a pivot drops whatever sorts late however often it occurs. Cells are summarised with `op`, defaulting to `sum`, since two rows can land in one cell. A column no row in a group reaches is absent rather than zero | 6 |
| `countpattern` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`reshape-matrix`) | Counts words in a text column. The pattern defaults to `[\w']+`, so an apostrophe holds a word together. `stopwords` is anchored to the whole token and matched case-insensitively, so `the\|on` drops those two words and not every word containing them. Counts come out in first-appearance order rather than sorted | 6 |
| `quantile` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`statistics`) | Samples a distribution at evenly spaced probabilities. With no `probs`, the sample points are the **midpoints** of `step` equal intervals — `(i + 0.5) / step`, so 100 steps run 0.005 to 0.995 and never reach either extreme. The quantile itself interpolates linearly between the two neighbouring order statistics, d3's `quantile` rather than a nearest-rank rule, so a median of an even count is the mean of the middle pair | 6 |
| `regression` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`statistics`, `trend-lines`) | All seven methods — `constant`, `linear`, `log`, `exp`, `pow`, `quad`, `poly`. The two straight ones come back as the fitted line's **two endpoints**; the curved ones are handed to the adaptive sampler, so their row count follows the data rather than a parameter. `params` swaps the points for `{coef, rSquared}`, in each method's own form: `pow` reports a multiplier and an exponent, the polynomials their terms from the constant upward. A group with no more points than the fit has parameters is skipped with a warning rather than fitted exactly through its own data. `exp` is fitted with residuals weighted by y rather than by taking logarithms, which is a different answer, not a rounding of the same one | 6 |
| `loess` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`trend-lines`) | A separate tricube-weighted straight line per point over its nearest neighbours, with three robustness passes re-weighting by residual against the median so an outlier stops dragging its neighbourhood. Output is one point per **distinct x**, rows sharing one being averaged. `bandwidth` is a fraction of the data, 0.3 by default — and with few enough rows that window falls to two points, where a local line passes through both and the smoothing silently does nothing | 6 |
| `kde` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`density-plot`) | A Gaussian bump over every observation, added up: the smooth curve a histogram approximates, and one that depends on the bandwidth rather than on where bin edges happen to fall. An unset `bandwidth` comes from Scott's rule. `cumulative` gives the distribution function instead, `counts` scales a probability by the group's size so unequal groups compare by area, and `resolve: "shared"` puts every group on one domain and a **uniform** grid — adaptive sampling would give each its own x positions and leave nothing to stack. The support is taken unfiltered, as upstream does, so a null in the column turns the density into NaN rather than silently narrowing it | 6 |
| `density` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`density-plot`) | Samples a named distribution rather than estimating one: `normal`, `lognormal`, `uniform`, a `kde` over a field, or a weighted `mixture` of any of those, as `pdf` or `cdf`. The normal CDF is West's (2009) rational approximation, transcribed rather than derived — there is no closed form. `extent` is required, since a distribution has no data to take one from; a `kde` distribution is the exception and may read its own | 6 |
| `dotbin` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`density-plot`) | Wilkinson's dot-plot stacking, which is **not** a histogram with round marks: there are no fixed bin edges. A stack opens at the first value that did not fit within `step` of the one before, and every dot in it sits at the midpoint of that stack's first and last value, so stacks land where the data is dense. `step` defaults to a thirtieth of the **whole field's** extent rather than the group's, so faceted dot plots stay comparable. `smooth` runs the variance-reducing swap pass, which moves dots away from their own value in exchange for a less jagged outline. Alone among these, it adds a field to the existing rows rather than replacing them, so the output keeps the input's order | 6 |
| `stratify` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`treemap`) | Reads a parent-child structure out of two columns. The output is the **input, unchanged and in order** — the tree is carried to the layout after it and never reaches a mark, which is why no part of the data model had to learn about trees. The tree belongs to the **dataset**, not to the pipeline run: a dataset that sources from this one inherits it, which is how Vega's own tree examples put `treelinks` in a `links` dataset of its own, and how upstream reaches it as `source.root`. Two roots, a parent key naming no row, a duplicated key or a cycle are each reported and stop the pipeline: a tree assembled from ambiguous links is a different tree, not a smaller one, and every layout drawn from it would be silently wrong | 6 |
| `nest` | **Supported** | `TransformReferenceTest` (upstream vectors) | Builds a tree by grouping where `stratify` builds one from links; each key adds a level. The interior nodes are invented and appear in the output only under `generate`, which emits them level by level from the root — not in the pre-order the layouts walk. Upstream also nests each group's own rows under a `values` column, a tree inside a field with no equivalent here; that omission is reported | 6 |
| `treemap` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`treemap`) | All six tilings. `squarify` (the default) makes each rectangle as near square as it can, because area is what a reader judges and a sliver's cannot be — at the cost of scrambling sibling order, which `dice`, `slice`, `slicedice` and `binary` all keep. Half the inner padding comes off each side of a parent, so a gap between two siblings is one padding rather than two. `resquarify` exists upstream to hold rectangles still while data animates; nothing animates here, so it tiles as `squarify` and says so | 6 |
| `partition` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`treemap`) | An icicle plot: every level of the tree gets an equal band of the height whatever its values, and each node dices its width among its children. Spends one axis on depth where a treemap spends both on quantity, so the same tree through the two reads like two different datasets | 6 |
| `pack` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`tree-layouts`) | Nested circles. A leaf's radius is the **square root** of its value so that area carries the quantity, as with a treemap; unlike one, circles cannot tile, so a pack always leaves gaps and reads as grouping rather than as proportion. Siblings are packed by a front chain and enclosed by Welzl's algorithm over a *seeded* shuffle, so the same data packs the same way every time. `radius` is resolved against the **layout node** rather than the row — upstream's own behaviour — so naming a data column gives every circle a radius of zero; matched rather than corrected, and reported | 6 |
| `tree` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`tree-layouts`) | Both methods. `tidy` is Reingold-Tilford in Buchheim's linear-time form, which guarantees that identical subtrees are drawn identically wherever they appear; `cluster` is a dendrogram, putting every **leaf** on the last row whatever its depth, because in a clustering result the leaves are what is being compared. `separation: false` packs cousins as tightly as siblings. `size` fits the diagram to a box, `nodeSize` fixes the spacing per node and lets the diagram be whatever size follows | 6 |
| `treelinks` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`link-paths`) | Turns a tree back into a row per edge, each holding the two rows **whole** under `source` and `target` — not their fields merged, since both ends carry the same column names. Edges come out **breadth-first**, the order `d3-hierarchy`'s own iterator walks, which is the order they are painted in. The output replaces the input, so a `links` dataset holds edges rather than nodes, and the tree stops there. A node whose row is no longer present emits no edge, as upstream's tuple lookup does; and because transforms here copy rather than mutate, a node is matched to its row by position, so a transform that adds or drops rows between the two is reported instead of guessed at | 6 |
| `linkpath` | **Supported** | `TransformReferenceTest` (upstream vectors), `FixtureDifferentialTest` (`link-paths`) | All twelve shape and orientation pairings upstream defines. `line`, `arc` and `curve` are symmetric in x and y, so a Cartesian `orient` falls through to the bare shape; `orthogonal` and `diagonal` bend towards the axis the tree grows along and exist only per orientation. Under `radial` the four accessors are **angle and radius** rather than x and y, and the path is emitted around the origin for the mark's own `x`/`y` to place. Numbers go into the path text the way JavaScript concatenates them, so the string is upstream's character for character. `require` names a signal that should re-run the transform; nothing re-runs here, and that is reported | 6 |
| The other 7 transforms | Not implemented | `TransformReferenceTest` | An unimplemented transform stops the pipeline and reports it, so later stages never run on data they were not meant to see | 4+ |
| Tuple identity, change sets | Supported | `DataflowTest` | Data model only; the transform pipeline does not use it yet | 0 |
| Deterministic operator scheduling | Supported | `DataflowTest` | Topological ordering only | 0 |
| Pulse propagation / incremental evaluation | Not implemented | — | Transforms currently recompute a whole dataset. The `DataflowOperator` contract exists; there is no incremental engine behind it | 4 |
| Geo transforms, force layout | Not planned | — | Reports `VEGA_TRANSFORM_NOT_IMPLEMENTED` | — |
